# 2026-11-05

## 做了什么

- 新增 `tests/test_tcpserver.cc`（4 个端到端用例）：
  - `ConnectionCallbackFiresOnce`：连一次，断言 `connectionCallback` 只调一次；
  - `ConnectionReleasedAfterPeerClose`：对端断开后 `weak_ptr` 过期（ASan 下也跑过）；
  - `MultiIoThreadsNoCrossTalk`：`setThreadNum(4)`，16 个客户端各发各的 tag，回显不串；
  - `RebindAfterServerDestroyed`：析构 server 后同端口立刻能重新 bind。
- `tests/test_tcpconnection.cc` 重写 ⑤ `SlowConsumerOutputBufferBounded`：分块 4KB + 尊重水位，上界断言 `peak < 水位 + 一块`。
- 修 `TcpServer::newConnection` 里 `connectEstablished` 被调两次的问题（删旧的那行）。
- `TcpConnection.h` 加 `outputBufferSize()`（只读观测口，须在 loop 线程调）。

## 为什么

- TcpServer 之前只有单元级覆盖，建连路径没有端到端用例；这次补上后立刻抓到 day27 引入的双调用 bug。
- 原 ⑤ 的断言是恒真式（一次 send 1MB），改成“生产者遵守水位”的写法后，上界才有约束。

## 证据

- 全量：`144 tests from 23 test suites`，12.2s，全绿。
- 修复前 Debug 建连 abort：`TcpConnection.cc:712: Assertion 'state_ == kConnecting' failed`，gdb 栈从 `TcpServer.cc:78` 进来。
- ⑤ 变异：去掉水位 gate 后 `peak = 1,040,448`，断言 `peak < 8192` 失败；恢复后通过。
- ASan 构建下 `ConnectionReleasedAfterPeerClose` 与 `SlowConsumer*` 均通过。
- ASan 144/144 全绿（16.6 s）；TSan 143/143（`-*SlowConsumer*`）全绿（21.6 s）。
  `SlowConsumer` 还没在 TSan 下单独跑过——它是唯一有跨线程 `std::thread` 的用例。

## 命令

```bash
cmake --build build --target unit_tests -j$(nproc)
./build/unit_tests --gtest_filter='TcpServerTest.*:TcpConnectionTest.*'
./build/unit_tests --gtest_filter='TcpConnectionTest.SlowConsumer*'
ctest --test-dir build --output-on-failure
```
