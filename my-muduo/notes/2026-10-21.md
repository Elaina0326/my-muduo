# 2026-10-21

## 做了什么

- day15（`d05c469`）：补齐服务端/客户端骨架，共 685 行：
  - `TcpServer`：Acceptor + `EventLoopThreadPool` + `map<name, TcpConnectionPtr>`；
  - `TcpClient`：单连接 + `Connector`，析构要求 loop 线程；
  - `Connector`：非阻塞 connect、`SO_ERROR` 判定、指数退避重连。
- 用临时 harness 做端到端验证：
  - 4 线程 × 1MB echo、半关闭（`bye` 后读到 EOF）、4 个并发连接；
  - `TcpClient` 的连接/回显/断开/自动重连；
  - `~TcpServer` 时清理存活连接。
- 结果：主干路径全部通过；`sendMulti` 2000 分片和 `sendFile + TAIL` 两个边界失败，
  确认是真实缺陷，不是 harness 写法问题。

## 为什么

`TcpConnection` 已经能收发，但“怎么接受连接、怎么分线程、怎么在析构时收尾”还没有答案。
先把 `TcpServer` / `TcpClient` 做出来，才能用真实端口和真实客户端验证；
`Connector` 单独拆开，是为了把非阻塞 connect 的一堆 errno 从 `TcpClient` 里隔离出去。

## 证据

- `d05c469`：`TcpServer.* 178` 行、`TcpClient.* 228` 行、`Connector.* 276` 行。
- 临时 harness：
  - echo / 1MB / 半关闭 / 并发 / TcpClient / 服务器析构均通过；
  - `sendMulti(2000)` 返回 `EINVAL`，客户端 0 字节；
  - 8MB 文件 + 4B `TAIL` 只收到 8,388,608 字节。
- 发现 `TcpConnection::sendFile` 的公共包装在手工打补丁时被误删过，
  头文件还有声明、实现没了；没有调用方所以链接不报错，属于“定时炸弹”。
